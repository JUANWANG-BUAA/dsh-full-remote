# dsh-full-remote v0.5.0

[English](#english) · [中文](#中文)

## English

### Task cockpit for phones and remote desktops

- A minimizable **Task cockpit** appears on remote hostnames or phone-width viewports. Phones use a full-width bottom sheet; wider remote windows use a compact right-side panel. Both follow the Harness light/dark theme, support long content and safe-area spacing, and retain access to confirmation controls.
- **Needs you** brings together each session's highest-priority official tool approval, question or plan review. Select an item, return to the inbox, switch tabs or minimize without cancelling it. The cockpit reuses official interactions and session navigation, not a replacement chat client.
- **Sessions** shows the official session list/order, running or unknown state, stopped activity to review and page-lifetime last-opened navigation. Unknown does not mean completed; a first-load list is not presented as empty.
- Drafts and submission locks survive switching/minimizing **within the same mounted page**. Reload, unload or session-service reconstruction clears them; resolution/removal clears the relevant form. No cross-reload draft persistence is promised.
- Connection handling is a **read-only observer of the host carrier**, not a second WebSocket or a new permission role. Disconnected/unknown submissions are disabled and guarded again at the action boundary. Sent actions stay locked while the official registry updates; uncertain outcomes are not automatically retried. Connected is not synchronized: displayed data is last known, and recovery requests a coalesced refresh.

### Compression, caching and active sessions

- Strict q-value negotiation adds **Brotli quality 4** alongside existing **gzip level 6**. Equal weights prefer Brotli; an explicitly higher identity preference is respected. Request/response `no-transform`, upstream encodings, SSE, WebSocket, ranges, fonts and known sub-1-KiB bodies retain their boundaries. Transformation merges `Vary`, weakens strong ETags and removes invalid length/digest metadata.
- Strictly admitted hashed assets use **private immutable browser caching**, replacing the historical generated public policy. Device-isolated encoded variants use an **8 MiB / 128-entry** LRU, **1 MiB per entry including metadata**, and at most **five minutes** freshness, shortened by upstream age/freshness. Authentication/CIDR checks precede cache hits; revocation, rotation and stop invalidate relevant entries. HTML, dynamic API/chat, credential-bearing requests, `Set-Cookie` and unknown `Vary` are not admitted.
- Conditional static hits can return 304 without upstream work; fresh browser caches may avoid the request entirely. Revocation cannot erase previously downloaded browser assets. No cross-device variant sharing is introduced.
- An owned bounded upstream keep-alive pool is destroyed on stop. Real HTTP/WS bytes maintain device activity, with one-second persistence notification throttling and quiet-lease checks. An open socket alone does not renew a session, and traffic never extends absolute TTL or crosses revoked credential generations. Invalid streams close both peers; no heartbeat injection, lossless reconnect promise or automatic write replay.
- Hidden settings pages pause device/tunnel polling and refresh once when visible. Slow requests remain single-flight per method. Cockpit automatic recovery refreshes coalesce at least five seconds apart; manual refresh shares the active flight.
- Existing `compressResponses` / `cacheHashedAssets` switches remain available. See [HTTP transport contract](https://github.com/JUANWANG-BUAA/dsh-full-remote/blob/v0.5.0/docs/http-gzip.md).

### Benchmark: measured gains and regressions

The baseline is the unmodified revision `0d4b48c8837ac4b11f3c477b1c04bde46c75f5d6`, **already using gzip L6**. Results use real local frontend HTML + four entry JS/CSS resources (**1,480,308 raw bytes**) over loopback HTTP/1.1: **15 measured paired rounds plus two excluded warm-ups**. These are per-round medians of summed HTTP issue-to-response-end times, excluding decode/assert, browser rendering, TLS, tunnels and mobile networks.

| Scenario | Baseline → 0.5.0 | Scope / trade-off |
|---|---|---|
| Cold-device entry body bytes | 415,637 → 415,534 B | Only 103 B / 0.025% smaller; do not count old gzip savings again |
| Cold-device HTTP time | 42.08 → 25.61 ms | −39.1% with negotiated Brotli; server/pool already warmed |
| 40 warm static requests | 40 → 0 upstream requests; 424.68 → 28.15 ms | −93.4% local HTTP time, not overall page speed; downstream still about 4.15 MB |
| 40 conditional responses | 40 → 0 upstream requests; 24.10 → 17.51 ms | Both versions already return 0 B bodies |
| Conditional complete downstream HTTP bytes | 6,360 → 9,800 B | **+54.1%** from extra headers, +86 B/response |
| Ten synthetic JSON API requests | 8.82 → 10.25 ms | **+16.2%** HTTP time despite smaller bodies; no API caching |
| Cold gzip-only control | 42.08 → 44.20 ms | **About +5.0%** overhead; warm gzip-only still improves to 27.88 ms |

Brotli Q4 is slightly larger than gzip L6 for the measured vendor JS (178,714 vs 178,527 B) and index CSS (15,424 vs 14,610 B). In fake-clock tests of real React components, hidden polling is 50 → 0 RPC/60 seconds, visible remains 50, slow RPC calls are 48 → 20, and peak total in-flight calls 5 → 2. These are not measured battery savings. Deterministic real-SSE/session-clock observations are not wall-clock endurance tests. No physical-phone LCP/INP, weak-network, production throughput or CPU/RSS improvement is claimed.

Read the [full English report](https://github.com/JUANWANG-BUAA/dsh-full-remote/blob/v0.5.0/docs/performance-benchmark.md), [中文报告](https://github.com/JUANWANG-BUAA/dsh-full-remote/blob/v0.5.0/docs/performance-benchmark.zh.md) and fixed [summary](https://github.com/JUANWANG-BUAA/dsh-full-remote/blob/v0.5.0/docs/benchmarks/v0.5.0/summary.json) / [transport](https://github.com/JUANWANG-BUAA/dsh-full-remote/blob/v0.5.0/docs/benchmarks/v0.5.0/transport.json) / [polling](https://github.com/JUANWANG-BUAA/dsh-full-remote/blob/v0.5.0/docs/benchmarks/v0.5.0/polling.json) / [session](https://github.com/JUANWANG-BUAA/dsh-full-remote/blob/v0.5.0/docs/benchmarks/v0.5.0/session.json) evidence. ### Upgrade

Use the GitHub release tarball (the same `plugin --profile web add` syntax as the README):

~~~sh
dsh plugin --profile web add https://github.com/JUANWANG-BUAA/dsh-full-remote/releases/download/v0.5.0/dsh-full-remote-0.5.0.tgz
~~~

Or download and install locally:

~~~sh
curl -fLO https://github.com/JUANWANG-BUAA/dsh-full-remote/releases/download/v0.5.0/dsh-full-remote-0.5.0.tgz
dsh plugin --profile web add ./dsh-full-remote-0.5.0.tgz
~~~

Restart the Harness process serving the `web` profile and reload connected browsers to load the new server/client bundle. Use the release SHA-256 file to verify the downloaded artifact. GitHub tarball distribution does **not** itself confirm npm publication; only if the registry provides 0.5.0 is the registry alternative `dsh plugin --profile web add dsh-full-remote@0.5.0` applicable.

### Verification

Release validation passed **303 server/unit tests and 127 client tests**, coverage gates, both TypeScript checks, the composition smoke and public-audit checks. An isolated real-browser regression passed four viewports (320×568, 390×844, 844×390 and 1280×900) plus the Settings flow, with zero page errors. These checks did not require a paid live-model invocation, and emulated phone viewports are not physical-device acceptance.

### Security and deliberate limits

**No RBAC or scoped/readonly sharing is added.** A device session is still privileged remote Harness access, not a multi-tenant boundary. The cockpit's read-only connection observation is not a read-only user role. Share only with trusted operators. Proxy-management APIs remain loopback-only; the existing token/device authentication, approval, CIDR and audit boundaries remain in force.

No PWA, background push, reload-persistent drafts, replacement chat, automatic write retry or guaranteed synchronization/reconnect recovery is included. A desktop browser with an emulated phone viewport is not physical iOS Safari/Android Chrome acceptance.

## 中文

### 手机与远程桌面的任务控制台

- 可最小化的**任务控制台**在远程 hostname 或手机宽度视口出现。手机使用全宽底部 sheet，较宽远程窗口使用右侧紧凑面板；跟随 Harness 明暗主题，支持长内容、安全区与可达的确认操作。
- **需要你**汇总每个会话最高优先级的官方工具审批、问题或计划审核。可选择事项、返回收件箱、切换标签或最小化而不取消事项；复用官方交互与会话导航，不另造聊天客户端。
- **会话**展示官方列表/顺序、运行/未知状态、停止后待查看的活动，以及页面生命周期内的最近打开标记。未知不是已完成；首次加载也不会伪装成空列表。
- 草稿与提交锁在**同一已挂载页面**内切换/最小化时保留；刷新、卸载或会话服务重建后清空，事项解决/移除后清理对应表单。不承诺刷新后草稿持久化。
- 连接处理是对**宿主 carrier 的只读观察**，不是第二条 WebSocket，也不是新增的只读权限角色。断线/未知时禁用提交，动作边界再次检查；提交后等待官方 registry 更新，结果不确定不自动重试。connected 不等于同步完成，显示的是最后已知状态，恢复时请求合并刷新。

### 压缩、缓存与活跃会话

- 在已有 **gzip level 6** 上增加 **Brotli quality 4** 的严格 q 值协商；同权重优先 Brotli，尊重显式更高的 identity 偏好。遵守请求/响应 `no-transform`，保持上游编码、SSE、WebSocket、Range、字体和已知小于 1 KiB 主体边界；变换时合并 `Vary`、弱化强 ETag、移除失效长度/摘要。
- 严格准入的 hash 静态资产使用 **private immutable 浏览器缓存**，替代历史自动生成的 public 策略。设备隔离的已编码缓存为 **8 MiB / 128 项** LRU，**每项含元数据最多 1 MiB**、新鲜期**最多五分钟**并受上游时效缩短。命中前先认证/CIDR，撤销/轮换/停止清理相应项；不缓存 HTML、动态 API/聊天、带凭据请求、`Set-Cookie` 或未知 `Vary`。
- 条件静态命中可 304 免回源，新鲜浏览器缓存还可完全免请求；撤销不能擦除浏览器已下载资产，不增加跨设备 variant 共享。
- 代理自有有界上游 keep-alive 连接池，停止时销毁。实际 HTTP/WS 字节更新设备活动，持久化通知限频一秒，静默租约每秒检查。打开 socket 本身不续期，流量不延长绝对 TTL、不跨已撤销凭据代次；失效流双端关闭。不注入保活，不承诺无损重连，不重放写操作。
- 设置页 hidden 暂停设备/隧道轮询，visible 恢复一次；慢请求按方法 single-flight。控制台自动恢复至少相隔五秒合并，手动刷新共享当前 flight。
- 保留 `compressResponses` / `cacheHashedAssets` 开关，详见 [HTTP 传输约定](https://github.com/JUANWANG-BUAA/dsh-full-remote/blob/v0.5.0/docs/http-gzip.zh.md)。

### Benchmark：收益与回归都公开

基线为未经改写的 `0d4b48c8837ac4b11f3c477b1c04bde46c75f5d6`，**旧版已经有 gzip L6**。使用本机真实 frontend HTML + 四个入口 JS/CSS（**原始合计 1,480,308 B**），loopback HTTP/1.1，**15 个计入统计的配对轮次，另两轮预热不计**。时间是每轮串行 HTTP 请求「发出到完整读完」耗时之和的中位数，不含解压/断言、渲染、TLS、隧道或手机网络。

| 场景 | 旧基线 → 0.5.0 | 范围与代价 |
|---|---|---|
| 冷设备入口主体字节 | 415,637 → 415,534 B | 仅少 103 B / 0.025%，不重复计算旧 gzip 收益 |
| 冷设备 HTTP 时间 | 42.08 → 25.61 ms | 协商 Brotli 下 −39.1%；服务与连接池已预热 |
| 40 次热静态请求 | 回源 40 → 0；424.68 → 28.15 ms | 本地累计 HTTP −93.4%，不是页面整体加速；下游仍约 4.15 MB |
| 40 次条件响应 | 回源 40 → 0；24.10 → 17.51 ms | 两版本来均为 0 B 主体 |
| 条件响应完整下行 HTTP 字节 | 6,360 → 9,800 B | 额外响应头导致 **+54.1%**，每响应多 86 B |
| 十次合成 JSON API | 8.82 → 10.25 ms | 即使主体更小，HTTP 耗时仍 **+16.2%**；没有缓存 API |
| gzip-only 冷路径对照 | 42.08 → 44.20 ms | **约 +5.0%** 开销；gzip-only 热路径仍降至 27.88 ms |

真实 vendor JS 的 Brotli Q4（178,714 B）比 gzip L6（178,527 B）略大，index CSS 也是 15,424 vs 14,610 B。真实 React 组件的模拟时钟测试中，隐藏 60 秒 RPC 50 → 0，普通可见仍为 50；慢 RPC 48 → 20，总峰值在途 5 → 2。这不是实测省电比例。真实 SSE + 可控会话时钟的确定性观测也不是墙钟耐久测试。不声称测得真实手机 LCP/INP、弱网、生产吞吐或 CPU/RSS 收益。

### 验证

发布验证通过 **303 项服务端/单元测试与 127 项客户端测试**、覆盖率门禁、两套 TypeScript 检查、composition smoke 与公开审计检查。隔离的真实浏览器回归通过 320×568、390×844、844×390、1280×900 四种视口及 Settings 流程，页面错误为零。未为此调用付费真实模型，模拟手机视口不等于真机验收。

### 安全与明确不做的事

**不增加 RBAC、分权限/只读分享。** 设备会话仍是高权限远程 Harness 访问，不是多租户隔离；只读连接观察不等于只读用户角色。只分享给可信操作者。代理管理 API 继续限 loopback，现有令牌/设备认证、审批、CIDR 与审计边界保持生效。

本版不包含 PWA、后台推送、刷新后草稿持久化、替代聊天客户端、自动写重试或必达同步/重连恢复保证。桌面浏览器模拟手机视口，不等于真机 iOS Safari / Android Chrome 验收。
